# 轮回：游戏体验与内容底座

日期：2026-09-09。本文是当前体验方向与后续内容制作约定；历史原版资料保留在 `PROTOTYPE_DESIGN.md`。以下明确区分已实现界面与待开发玩法，节奏、人数、性能指标均是待验证目标。

## 1. 产品主张

**与一只灵宠、几个同行者，走进会回应你的山川。**

定位是国风轻奇幻共游冒险。美的人物、值得驻足的风景是进入理由；观察环境、选择路线、配合破局、带回独特收获才是留下理由。保留“轮回”的跨世界想象力，但第一阶段不追求地图数量，不依赖每日清单、连续弹窗和数值膨胀撑在线时长。

玩家扮演成年旅人。角色应有自然的面部结构、不同气质和完整服装设计，不用磨皮、统一尖下巴或过度暴露代替美感。女性角色是重点样板，男性与其他角色遵守同一材质、比例和光照标准。

## 2. 一个可以记住的核心机制：山川回响

这是下一阶段的机制设计，**本轮尚未实现**。

同一片场景同时保留“眼前的山川”与“发生过的往事”。旅人通过现场线索，短暂唤起局部回响：断桥出现旧时倒影、熄灭的灯指出另一条路、守卫在过去留下的破绽重新显现。不是复制两套大地图，而是在少量地标周围改变路径、对象和遭遇。

每段旅程至少提供三种有代价但都成立的选择：

- **探路**：绕行找到旧路，遭遇较少，但需要观察环境。
- **破阵**：正面打断守卫的阵眼，得到战斗材料，承担更高风险。
- **结伴**：与同行者或灵宠保持两处回响，开启合作路径；单人有更慢但可完成的替代过程。

选择必须影响当局路线、遭遇或奖励类型，不能只换一句对白。每局可用的线索组合不同，但因果关系稳定，不做纯随机找开关。

灵宠的价值从“跟随加战力”走向“改变解题方法”：例如感知隐路、暂时承受机关冲击、留下一个持续共鸣点。正式名称和能力从服务端内容配置读取；现有宠物主动技能保持可用，不把这些提案写成已开放天赋。

## 3. 第一片区：花溪小镇与枫桥驿站

先把已有小镇和枫林做成一段完整旅程，暂停同时扩张其他主题。其他世界保留资源与访问能力，但不作为首批品质承诺。

| 节拍 | 玩家实际行为 | 设计检验 |
| --- | --- | --- |
| 相逢，约1分钟 | 看见角色与地标，获得一个现场目标 | 不看说明书也能找到第一处互动 |
| 发现，约2分钟 | 沿花瓣、灯光或声音找到回响线索 | 去掉任务箭头后仍能靠场景判断方向 |
| 选择，约2分钟 | 决定穿过旧桥或正面破阵 | 两条路的风险和结果有差别 |
| 合作，约2分钟 | 运用灵宠或同行者能力处理阻碍 | 不只是四个人同时攻击同一个血条 |
| 高潮，约2分钟 | 从前面线索识别守卫招式并打断 | 被击中能看懂原因，手机触控有躲避余量 |
| 回程，约1分钟 | 带回材料、回忆或外观收藏，决定下一次尝试 | 收获用途明确，不强制立刻弹充值或强化窗口 |

以上约10分钟为完整短旅程目标，也允许随时退出。失败保留已确认的发现，不发未完成奖励；重进恢复检查点，不让客户端自行补发。

第一片区只需一条主路线、两条可选路径、三处地标、一种机关、两种普通敌人、一名守卫、两只互补灵宠。相同机制在第二次游玩时交换线索和风险，不靠增加十倍资产获得重玩。

## 4. 三层循环

1. **当下30秒**：观察预警，移动、普攻、技能与灵宠指令有取舍。清晰反馈优先于铺满粒子。
2. **一段约10分钟**：发现线索，选路，处理一次关键遭遇，确认收获。
3. **长期数周**：形成自己的武器与灵宠搭配，补完旅途记录，与固定同行者完成更难路线，解锁外观与地标故事。

装备先做横向差异：更擅长破势、支援、机动的不同搭配；基础成长仍存在，但避免必须强化才能体验普通内容。盟会先承担“找到稳定同行者”和共同记录的作用，再做领地竞争。交易在物品来源、库存和结算安全可靠后扩张，不能提前承担核心留存。

自动化只是一种辅助。本轮现有“自动任务”仍包含自动移动和战斗，入口保持明确，不改名伪装成纯寻路。后续实现回响机关时必须明确自动模式如何暂停，不能自动完成关键选择，也不能在打开菜单后继续消耗物品。

## 5. 本轮已落地的体验结构

### 世界

- 左上角色状态和当前任务；右上地图和旅途入口。
- 中央留给场景、目标和战斗预警；左下移动，右下战斗。
- 不常驻全宽系统导航栏。镜头缩放继续支持双指，观景模式保留独立缩放控制。
- 点击任务打开当前旅程，不因为身处小镇就跳过当前收集任务传送到枫林。

### 旅途

- 直接读取当前地图、目标、目标进度和回忆数量，不维护第二套任务或奖励数据。
- 地图与回忆提供空间和收集入口，宝山是历练入口；装备、灵宠、同游、盟会为固定系统分类。
- 行囊、称号、容貌与设置作为次级操作，避免新增业务就增加一枚世界按钮。
- 返回世界保持原地图和位置，不自动开战、不扣资源。

### 页面与弹层

- 导航目录统一维护合法路由、标题、图标和主分类。页头独占角色与银两信息；页面只提供自己的内容。
- 建角的角色展示、性别、职业、昵称与确认区域互不抢占触摸位置。
- 容貌编辑左侧是实时人物，右侧是五官、发型、色彩；预设与确认区不盖住脸。
- 同游的聊天、队伍、集市分视图；未登录的在线系统显示明确登录入口。
- 打开弹层停止移动与自动任务，关闭恢复原页面；取消容貌编辑不改变已存外观。

## 6. 代码与内容职责

| 所属 | 负责 | 不负责 |
| --- | --- | --- |
| `PrototypeNavigation` | 页面目录、系统壳、旅途中枢 | 计算掉落、模拟玩家、复制任务进度 |
| `AdventureHud` | 展示战斗状态、转发用户意图 | 自行传送跳任务、处理奖励结算 |
| 各系统页面 | 选择、表单、操作确认、状态展示 | 跨页面拼接一套独立导航 |
| `AdventureCombat` / 在线快照 | 当前已有冒险与任务状态 | 对未实现机制展示虚假的完成进度 |
| `NativeGameClient` | 协议调用与服务端已确认数据 | 将本地演示资源冒充在线资产 |
| 现有 logic / provide 配对模块 | 权威规则、校验、持久化与契约 | 接受客户端传入“我已获奖”作为事实 |

不新增空的“玩法总管理器”或另一套客户端经济模型。新规则进入实际拥有状态的业务模块，协议放对应 provide；有重复状态时先合并所有权，再考虑抽象。

## 7. 后续内容的最小契约

扩展现有地图、任务与事件契约，而不是先新建通用工作流引擎。一个可发布的片区内容包至少应能回答：

| 内容 | 必须有的信息 |
| --- | --- |
| 身份 | 稳定地图ID、内容版本、所需客户端资源版本 |
| 入口 | 前置条件、出生点、退出点、可恢复的检查点 |
| 发现 | 地标ID、线索触发条件、可读的场景反馈 |
| 选择 | 选项、服务端前置校验、锁定规则、对路线或遭遇的影响 |
| 遭遇 | 敌人配置、空间范围、危险预告、失败恢复规则 |
| 协作 | 人数范围、单人替代、掉线与队长离开处理 |
| 结算 | 完成条件、奖励表引用、重复领取防护、背包满处理 |
| 表现 | 模型、动画、音效、预警、低画质替代与缺失资源兜底 |

客户端提交“操作意图 + 对象ID + 版本/序号”，服务器判定是否成立。节点转换、结算和奖励必须可重放验证；重复请求只产生一次结算效果。掉线重连获取已确认快照，不信任客户端倒计时或本地进度推断。

组队先采用共享城镇加小队冒险实例，目标四人。暂不承诺无缝大世界、跨服战争、百人同屏或玩家自由建造。它们会放大同步、内容与运营成本，不能解决第一段冒险不好玩的问题。

## 8. 审美与制作门槛

- 主方向为明净山水、克制奇幻：中性墨色界面、青玉表示可用或恢复、金色表示选中或稀有、朱红表示危险，颜色承担含义。
- 每个片区只确定一个主地标、一个材质主题、一个主要光照关系。删掉无关装饰，再增加资产密度。
- 人物先验收正面、侧面、四分之三视角及待机/跑动，之后才增加妆容。鼻翼、眼睑、唇线、发际线和颈部衔接优先于贴图分辨率。
- 不把未经处理的AI网格直接当角色。沿用现有骨骼与动画，逐步替换经重拓扑、UV、材质、绑定和移动端预算验收的部件。
- UI 控件拥有稳定触摸区域；标题只表达所在页面，不重复讲解功能；长文本按真实内容验证，而非只用两个字的样例。
- 美术、音频与字体在进入正式构建前记录来源、许可与修改情况；购买资产前先在实际手机光照中验证一个样本。

## 9. 按完成定义推进

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 本轮：体验骨架 | 世界HUD、旅途、统一导航、基础布局及回归 | 四种横屏比例无控件交叠；原有成长操作不回归；入口可来回返回 |
| 下一轮：一个片区 | 一处回响机关、两条路线、一场完整守卫战 | 首次玩家无需口头指导可完成；第二次能说出不同选择的意义 |
| 再下一轮：共游 | 同一片区双人至四人合作 | 加入、退出、重连、重复提交、结算幂等全部通过 |
| 品质样板 | 一名女性角色、一只灵宠、一个场景的完整美术与音频 | Android实机远近镜头、动作、表情、光照一致；不依赖静态截图掩盖问题 |
| 扩展内容 | 复用机制增加片区，而非新写一套系统 | 新片区以配置和资源为主；新增规则有所属模块及独立测试 |

测试节奏优先记录：找到第一个目标用时、任务与菜单误触、死亡原因理解率、第二次主动换路比例、组队完成率。暂不把总在线时长或功能数量当作品质。

移动端初步目标为中档机稳定30帧，高档机可选60帧；具体设备、内存、温度和帧时间必须真机采样后定预算。编辑器截图不能证明手机性能、弱网稳定性或多人玩法质量。

## 10. 本轮验证入口

团结编辑器执行 `Lunhui.Prototype.PrototypeValidation.RunBatch`，参数 `-lunhuiLayoutOnly -lunhuiValidationOutput <输出目录>`，保留图形设备，不传 `-quit` 或 `-nographics`。检查完成自动退出，失败返回非零。

此模式复用已有 Boot 场景，不生成地图与人物资源；输出逐页截图、像素非空检查、控件范围与重叠检查、旅途往返及原有战斗/成长交互回归。在线页面样本验证仅检查呈现与本地交互，不代表真实服务器与多人联网验收。
